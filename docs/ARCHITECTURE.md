# «Пока жду» — архитектура

Мобильный PWA для краудсорсинговой разметки коротких клипов с уличных камер.
Человек сканирует QR-код на остановке и за 1–3 минуты отвечает на вопрос
«Человек в рамке курит?» для 3–5 клипов. Ответы нужны для обучения модели.

## 1. Компоненты

```
 QR (?stop=1284)
      │
      ▼
┌───────────────────────────┐        ┌──────────────────────────────┐
│  PWA (React + Vite, TS)   │  /api  │  API (FastAPI, Python 3.12)  │
│  • онбординг, разметка    │ ─────► │  • выдача клипов             │
│  • service worker (shell) │        │  • приём ответов, антиспам   │
│  • очередь ответов офлайн │        │  • агрегация меток           │
│  • /admin (ленивый чанк)  │        │  • статистика, админка       │
└────────────┬──────────────┘        └───────┬───────────┬──────────┘
             │ подписанный URL (5–10 мин)    │           │
             ▼                               ▼           ▼
     ┌───────────────┐                 ┌──────────┐  ┌──────────────┐
     │ S3-хранилище  │◄── загрузка ────│ CLI seed │  │ PostgreSQL   │
     │ клипы MP4     │    (пайплайн)   │ / import │  │              │
     └───────────────┘                 └──────────┘  └──────────────┘
```

* **nginx** раздаёт статику PWA (с долгим кэшем для хэшированных ассетов),
  проксирует `/api` в бэкенд, ставит заголовки безопасности (CSP и др.)
  и даёт первый слой rate limiting.
* **Бэкенд** — один stateless-процесс FastAPI (масштабируется горизонтально),
  вся логика в SQL-транзакциях PostgreSQL.
* **Хранилище клипов** — S3-совместимое (локально SeaweedFS; в проде AWS S3, Yandex Object Storage, MinIO и т.п.). Клиент получает
  только короткоживущие подписанные URL. Для разработки без S3 есть
  `STORAGE_BACKEND=local` (файлы с диска, URL подписан HMAC).
* **Пайплайн подготовки клипов** (вне репозитория): нарезка 3–5 с, удаление
  звука, размытие лиц и номеров, H.264 ≤720p ≤1 МБ, детекция человека → трек
  рамки. Результат загружается в S3 командой `python -m app.cli import-clips`.

## 2. Модель данных

```
stops 1───* assignments *───1 clips 1───0..1 gold_clips
              │  1                   1
              │                      │
              └──0..1 answers *──────┘
users 1───1 user_stats      users 1───* answers      clips 1───* clip_reports
```

| Таблица        | Назначение |
|----------------|------------|
| `stops`        | Остановки из QR (`id`, `name`, `region`). Неизвестный `stop` не сохраняется. |
| `users`        | Анонимный UUID + время согласия. Без имён/email/телефонов. |
| `user_stats`   | Ответы, точность на золотых, **вес голоса**, блокировка, серия дней, длина серии одинаковых ответов. |
| `clips`        | Ключ в S3, длительность, размеры, **трек рамки** (`bbox` jsonb, координаты 0..1 по времени), денормализованное состояние разметки: `votes`, `label_state`, `final_label`, `confidence`. |
| `gold_clips`   | Ответ эксперта и пояснение (локализуемое) для обратной связи. |
| `assignments`  | Факт выдачи клипа пользователю. Ответ принимается только на выдачу → нельзя слать ответы на произвольные клипы; клиент не знает, какой клип золотой. |
| `answers`      | `clip_id, user_id, answer, sub_answer, response_time_ms, stop_id, created_at` + `status` (accepted/rejected), причина отбраковки, `ip_hash`. |
| `clip_reports` | Жалобы; клип сразу исчезает из выдачи пожаловавшегося, глобально — по порогу. |

Полная схема: [`backend/app/schema.sql`](../backend/app/schema.sql).

## 3. API

Все ответы — JSON. Авторизация пользователя — заголовок
`Authorization: Bearer <token>`, где `token = user_id.HMAC(user_id)`; токен
выдаётся при первом входе и хранится в `localStorage`. Cookies не
используются, поэтому CSRF-атака невозможна в принципе (браузер не
подставляет заголовок автоматически), плюс CORS ограничен списком origin.

| Метод | Путь | Что делает |
|---|---|---|
| `POST` | `/api/session` | `{consent: true}` → создаёт анонимного пользователя, возвращает `token`. |
| `GET`  | `/api/next-clips?stop=ID&n=3` | Выдаёт до 5 клипов: `assignment_id`, подписанный `url`, `duration_ms`, размеры, трек рамки. Флаги `limit_reached`, `exhausted`. |
| `POST` | `/api/answers` | `{assignment_id, answer, sub_answer?, response_time_ms}` → `accepted`, причина отбраковки, для золотого клипа — `gold: {match, expert_answer, explanation}`, обновлённый прогресс. |
| `POST` | `/api/reports` | `{assignment_id, reason}` — жалоба на клип. |
| `GET`  | `/api/stats?stop=ID` | «Вместе мы разметили M», вклад остановки сегодня, табло остановок, место. |
| `GET`  | `/api/me` | Ответы, точность, уровень и прогресс до следующего, серия дней, активность недели. |
| `POST` | `/api/me/consent` | Дать/отозвать согласие. |
| `DELETE` | `/api/me` | Удалить пользователя и все его ответы (метки клипов пересчитываются). |
| `GET`  | `/api/admin/summary` | Классы, состояния разметки, пользователи, жалобы. Требует `ADMIN_TOKEN`. |
| `GET`  | `/api/admin/agreement` | Cohen's kappa (попарно и с итоговой меткой), Fleiss' kappa. |
| `GET`  | `/api/admin/export?format=json\|csv` | `clip_id, bbox, final_label, votes, confidence, …` |
| `GET`  | `/api/admin/reports`, `POST /api/admin/clips/{id}/status` | Модерация жалоб. |

## 4. Выдача клипов (`/next-clips`)

1. Проверки: согласие, дневной лимит устройства, лимит IP (по `ip_hash`),
   лимит на «сессию» (скользящее окно 30 мин). При превышении — пустая
   выдача с `limit_reached`, фронт показывает «На сегодня хватит».
2. Для каждого слота с вероятностью `GOLD_RATE` (по умолчанию 12%) берётся
   золотой клип; новичку в первой выдаче гарантирован один золотой — чтобы
   быстрее оценить точность. Итоговая доля золотых в выдаче ≈ 10–15%.
3. Обычные клипы выбираются в порядке приоритета:
   1. `pending` — меньше 3 голосов; среди них меньше голосов → раньше;
      клипы, уже «занятые» достаточным числом незавершённых выдач, уходят в конец
      (чтобы не набрать 10 голосов, пока другие клипы стоят без ответа);
   2. `disputed` — 3+ голоса, но уверенность ниже порога (`CONSENSUS`, 0.7),
      и голосов меньше `MAX_VOTES` (7);
   3. клипы из того же района, что и остановка, — выше (контент «по месту»);
   4. случайный порядок внутри группы.
   Исключаются: уже виденные пользователем, скрытые/снятые, `done`.
4. Пользователь с очень низкой точностью (`is_blocked`) получает только
   золотые клипы — его ответы не попадают в датасет, но он может
   «реабилитироваться».
5. URL клипа подписывается на `CLIP_URL_TTL` (10 мин); клиент заранее
   скачивает следующий клип в `Blob`, поэтому истечение не мешает показу.

## 5. Качество данных

**Вес пользователя** (сглаженная точность на золотых, «Не уверен» не считается ошибкой):

```
acc_s  = (correct + 2) / (total + 3)          # новичок ≈ 0.67
weight = clamp((acc_s − 0.3) / 0.7, 0.05, 1)  # новичок ≈ 0.52, эксперт → 1
blocked, если total ≥ 6 и correct/total < 0.4; снимается при ≥ 0.5
```

**Итоговая метка** клипа — взвешенное большинство по 4 классам
(`cig`, `vape`, `no`, `unsure`), уверенность = доля веса победителя:

* `< 3` голосов → `pending`;
* `≥ 3` и уверенность `≥ 0.7` без ничьей → `done`;
* иначе `disputed` (клип снова в выдаче) до `MAX_VOTES = 7`, после — `done`
  с низкой уверенностью (видно в экспорте).

Метка пересчитывается после каждого ответа; экспорт всегда пересчитывает
все клипы по *текущим* весам (точность пользователей уточняется со временем).

**Антиспам** (отброшенные ответы сохраняются со `status = rejected` для аудита,
но не участвуют в агрегации и не идут в счётчики):

| Проверка | Правило |
|---|---|
| Слишком быстро | `response_time_ms < 1000` (фронт тоже не даёт ответить раньше) |
| «Пулемёт» | между двумя ответами пользователя по серверным часам < 300 мс |
| Одинаковые ответы подряд | серия ≥ 12 одинаковых ответов |
| Лимиты | 60 ответов/сутки на устройство, 30 за 30 минут, 400/сутки на IP |
| Rate limit запросов | 120 запросов/мин на IP в приложении + `limit_req` в nginx |
| Ответ без выдачи / повтор | 404 / 409 |

**Геймификация не поощряет скорость**: уровни требуют и количества ответов,
и точности на золотых клипах; нет таймеров, рейтингов скорости и денег;
отброшенные «быстрые» ответы не увеличивают счётчик.

| Уровень | Условие |
|---|---|
| Новичок | — |
| Наблюдатель | 25 ответов и точность ≥ 70% (минимум 3 золотых) |
| Эксперт | 100 ответов и точность ≥ 85% (минимум 10 золотых) |

## 6. Приватность и безопасность

* Клипы размыты в пайплайне; в приложении только показ, без звука, без
  адреса и времени съёмки. Клиенту не передаются `external_id` и ключи S3.
* О пользователе хранится только случайный UUID и время согласия.
  IP не хранится: только `HMAC(секрет, день + IP)` для дневных лимитов.
* Согласие — чекбокс в онбординге, без него ответы не принимаются.
  На странице «О проекте» можно отозвать согласие и удалить свои ответы.
* XSS: React экранирует вывод, `dangerouslySetInnerHTML` не используется,
  строгий CSP (`script-src 'self'`), `X-Content-Type-Options`,
  `Referrer-Policy: no-referrer`, `Permissions-Policy`.
* CSRF: токен только в заголовке `Authorization`, без cookies; CORS по списку.
* Валидация всех входных данных (pydantic, перечисления, длины, `stop` по regex).
* Подписанные URL клипов (S3 presign / HMAC) с TTL 10 минут.
* Админка закрыта `ADMIN_TOKEN` (сравнение за постоянное время).

## 7. Фронтенд

* React 18 + Vite + TypeScript, без UI-фреймворков. Основной бандл
  ≈ 50 КБ gzip; админка — отдельный ленивый чанк.
* Шрифт заголовков Roboto Condensed 600 (кириллица + латиница, `font-display: swap`),
  текст — системный шрифт. Критичный CSS маленький → первая отрисовка < 2 с на 4G.
* Service worker: precache оболочки, `network-first` для `/api`, клипы не кэшируются
  (подписанные URL).
* Предзагрузка: следующий клип скачивается в `Blob` заранее; следующая пачка
  запрашивается на экране итогов.
* Офлайн-очередь ответов в `localStorage` — на слабом интернете ответ не теряется.
* Видео: `muted playsinline autoplay loop`, рамка рисуется поверх по треку
  с интерполяцией по `currentTime`.
* Тема — по `prefers-color-scheme`, тап-зоны ≥ 48 px, вёрстка 360–430 px.
* i18n: `src/i18n/ru.ts` (по умолчанию) + `en.ts`; язык — `?lang=` или язык браузера.

## 8. Параметры (env)

См. [`backend/app/config.py`](../backend/app/config.py): `REQUIRED_VOTES=3`,
`MAX_VOTES=7`, `CONSENSUS=0.7`, `GOLD_RATE=0.12`, `MIN_RESPONSE_MS=1000`,
`SAME_ANSWER_RUN_LIMIT=12`, `DEVICE_DAILY_LIMIT=60`, `SESSION_LIMIT=30`,
`IP_DAILY_LIMIT=400`, `CLIP_URL_TTL=600`, `REPORT_HIDE_THRESHOLD=2`.

## 9. Этапы

1. **MVP** — онбординг, разметка, сохранение ответов, выдача с 3 голосами,
   золотые клипы, жалобы, «О проекте».
2. **Геймификация** — уровни, серия дней, табло остановок, анимации итогов.
3. **Админка и экспорт** — статистика, kappa, экспорт JSON/CSV, модерация жалоб.

Дальше (вне MVP): Redis для rate limiting при нескольких репликах, HLS для
очень слабых сетей, отдельная очередь модерации, A/B доли золотых клипов.
